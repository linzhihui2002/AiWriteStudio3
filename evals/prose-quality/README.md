# 中文小说短场景盲评

本目录提供第一轮文学质量评测入口：20 条自行编写的原创中文场景，比较当前流程与一个优化流程。它用于观察读感、人物声音、潜台词和修订成本；没有调用模型或产生产品效果结论。

脚本只使用 Python 标准库，不读密钥、环境中的供应商配置或小说数据库，不自动读取 `projects/`，不上传作者材料，也不调用任何 `dsh`。**不接入 pytest / CI**。运行自检只能证明评测工具按约定工作，不能证明小说质量提高。

## 文件与场景

| 文件 | 用途 |
|---|---|
| `cases.json` | 20 条原创虚构场景；事实约束、人物目标、知识边界、字数范围和评价维度 |
| `outputs.example.json` | 两方案输出与实验元数据的结构示例；里面的文本、模型信息与成本都不是实测 |
| `run_eval.py` | 离线字段校验、配对随机盲化和人工结果汇总 |
| `check_eval.py` | 独立标准库自检；不调用模型，不作为小说质量验收 |

场景包括借钱、房屋修缮、赶船、家庭试探、误读意图、职场澄清、窄桥脱身、火场逃生、追逐损失、修表掩饰、丧亲独处、欠薪开口、旧信、责任选择、时间转场、受伤后的衔接、传闻核实、儿童对白、日常误会和具体悬念。人物与情节均为本次新编，未使用第三方小说摘录。

每条练习要求 300–650 汉字，方便多场景比较。**这是短场景练习范围，不改变正式章节的 2000 字默认下限或任何硬门禁。** 第一轮通过后，还应增加连续数章评测，观察跨章复读、人物连续性与作者实际修改量。

## 第一步：只做离线校验

从仓库根目录运行：

```powershell
python evals/prose-quality/run_eval.py --dry-run
python evals/prose-quality/check_eval.py
```

`--dry-run` 只读取场景 JSON 并检查 schema、唯一 ID、事实卡、人物与知识边界、维度和字数范围。不会读取密钥、生成正文、建立评审目录或判定质量通过。自检使用临时目录验证脚本行为，结束后清理临时产物。

## 第二步：取得两方案实际输出

复制 `outputs.example.json` 到自行选择的数据目录，填入真实结果，并为每个场景添加两条 `candidates`。不要把示例占位文本当作模型结果。

本入口**没有自动生成模式**。可通过工作台已有的受控生成接口或显式导出的任务结果取得两方案文本，再整理成 JSON；生成调用仍须经过工作台 `generation_service`、本书权限与项目上下文规则。如果使用工作台 DSH 引擎，必须走锁定的 vendor 和 `engine/dsh_paths.py`，不得通过全局 `dsh` 或用户全局 `~/.dsh` 生成评测材料。脚本本身不会为了评测绕过这些约束。

第一轮建议比较“当前流程”与“审稿修订修复后的流程”；后续分别比较“增加作者认可样稿”和“增加场景生成”。每轮只变一个主要条件，固定事实、场景长度、模型版本、采样参数与预算。若故意比较不同模型，在元数据中完整登记，不能把结果全部归因为流程优化。

`experiment.conditions` 必须恰好包含两个方案。每个方案记录：

- `id`：内部方案 ID，如 `baseline` / `optimized`；不能用保留值 `tie` / `both_bad`。
- `label`：私有的人类可读名称，不进入盲评包。
- `provider`、`model`、`model_revision`：实际供应商、模型与版本；无法取得版本时明确填 `unknown`。
- `prompt_version`：实际提示版本。
- `parameters.temperature`：实际生效的温度；不支持或无法核实时填 `null`。
- `parameters.max_output_tokens`：生成时设置的输出上限。
- 可选 `prompt_hash`、`settings_hash`、`style_reference_hash`：已有任务快照中的小写 SHA256；缺乏依据时省略或填 `unknown`，不要伪造 hash。

`experiment.budget` 记录 `currency`、两方案合计每场景的 `max_cost_per_case`、每个方案的 `max_tokens_per_candidate`。脚本登记和报告实际观测到的超额，**不会自动执行或阻止付费生成**。

每个输出条目包含 `case_id` 与至多两条候选。候选必需 `condition_id` 和完整 `text`，可选 `usage`：

```json
{
  "condition_id": "baseline",
  "text": "这里是实际生成的完整场景正文。",
  "usage": {
    "cost_amount": null,
    "currency": "CNY",
    "prompt_tokens": null,
    "completion_tokens": null,
    "duration_ms": null
  }
}
```

已知成本必须与预算币种一致，不支持混合币种折算。成本和 token 应包含得到该候选所花费的全部生成、审稿与修订轮次；耗时也按同一范围记录。不知道的字段用 `null` 或省略，不能填零冒充免费。方案配置 hash、场景集 hash、全部输出 hash 和每条正文 hash 会由脚本确定性计算。

候选 `text` 只能放正文，提前移除生成器附加的方案标题、模型名称和评价。脚本保留正文原样用于追溯，不会删除正文里的词句来制造盲化；它只隔离元数据，不能消除作品本身可能暴露方案的信息。输入 schema 拒绝 `api_key` 等未知字段，请勿在任何实验文件中写入密钥。

## 第三步：建立盲评包

```powershell
python evals/prose-quality/run_eval.py prepare --outputs D:/eval-data/prose-outputs.json --out-dir D:/eval-data/prose-round-01 --seed 20261003
```

脚本用固定 seed 随机排列场景，并为每场景独立随机交换 A/B 展示位置。相同输入与 seed 在相同脚本版本下产生同一评审包与映射。未提供完整两方案的场景列为 `unpaired_case_ids`，不提供给评审者做胜负判断。已有输出文件会被拒绝覆盖，应为新实验选择新的目录。

输出目录：

```text
prose-round-01/
  review/
    packet.json     # 只含场景、盲化 A/B 正文、维度与正文 hash
    ratings.json    # 空的人工评分模板
  private/
    labels.json     # 原始方案映射、模型参数、成本和追溯 hash
```

**仅向盲评者分享 `review/`。** `private/labels.json` 与原始输出不交给盲评者；目录分开是分享约定，不是操作系统访问权限控制。评审完成并锁定裁决后才用私有映射揭盲。不要在评审过程中反复调 seed 选择有利排列。

## 第四步：填写人工裁决

每场景只保留一条最终裁决。可由单个读者填写，或由多个读者先独立判断再形成一条明确记录的共识；`reviewer_id` 记录实际读者或共识组，分歧可记入 `notes`。不要把同一场景的多名读者当成多个独立场景来扩大统计样本。

`preference` 的取值：

| 值 | 含义 |
|---|---|
| `"A"` | 更愿意继续阅读当前展示的 A |
| `"B"` | 更愿意继续阅读当前展示的 B |
| `"tie"` | 两者接近平局，无法形成偏好 |
| `"both_bad"` | 两者都不好，不能把较不差的一方当作成功 |
| `null` | 尚未裁决；留空或缺少整条记录都视为未评 |

完成偏好后，可以分别填写 A/B 的活跃维度，均为 1–5 的整数，分数越高越好。`restraint` 高分表示叙述更克制，避免反向理解。仅填写场景列出的维度；未评维度保留 `null`。对有 `null` 偏好的整条记录，工具不汇总其维度和修改量，避免半成品评价混进结果。

`fact_errors`：`null` 或缺字段表示尚未核查；`[]` 表示核查后未发现所列约束的错误；有错误时给出 `fact_id` 和具体理由。每个事实 ID 在同一候选内只记录一次，避免重复计数。未发现已列事实错误仍不等于语义完全正确。

```json
{
  "A": [{"fact_id": "F1", "detail": "正文把原设定的六枚铜钱写成八枚。"}],
  "B": []
}
```

`edits.A/B.characters` 是作者为达到愿意采用的状态而实际修改的字符量，按同一口径记录增、删、改字符；`minutes` 是实际修订分钟数。没有真的修改时填 `null`；完成核验且确实无需修改时才能填零。修改量口径、读者来源与评审环境应写入实验 `notes` 或保留在评审记录中。

## 第五步：汇总与揭盲

```powershell
python evals/prose-quality/run_eval.py score --packet D:/eval-data/prose-round-01/review/packet.json --labels D:/eval-data/prose-round-01/private/labels.json --ratings D:/eval-data/prose-round-01/review/ratings.json --out D:/eval-data/prose-round-01/report.json
```

汇总会校验 packet 与正文 hash、方案配置 hash、A/B 映射和评分 schema；错误退出码为 2，不会生成“通过”的结果。报告包含：

- 总场景、配对场景、已评与未评场景，缺失场景不会算通过。
- 原方案的胜出数、平局数和“两者都不好”数。
- 只在明确 A/B 偏好场景中计算的胜率及 95% Wilson 区间。若没有明确偏好，胜率与区间都是 `null`。
- 每个维度的均分、观测条数与缺失条数；缺失覆盖率以全部场景中该维度应评次数为分母，含未配对场景，不把缺失分数填零或满分。
- 已核查的事实错误数量、未核查覆盖率与实际修改量。
- 已知成本、token 与耗时的总量/均值和缺失覆盖率；未记成本不会按零成本估算。
- 观测到的预算超额，以及实验元数据和数据 hash。

胜率分母是明确偏好的场景数，最多 20，通常更少。例如 10 胜 / 20 次明确偏好得到 50%，95% Wilson 区间约 30%–70%；这不是精确优势的证明。场景非随机抽样，同一评审者和相似题材又会产生相关性，因此区间只是当次结果的描述性不确定性。必须同时看未评、平局、两者都不好、事实错误和修改量，不能只摘一个胜率宣传优化有效。

目前数据覆盖短场景，尚无真实模型生成或真人读者结论。未来长篇评测应额外准备作者授权材料和连续章节，独立登记使用范围，再通过工作台受控读取与生成；本脚本不会自动搜集作者小说。
