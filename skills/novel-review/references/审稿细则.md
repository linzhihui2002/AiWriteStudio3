# 审稿细则

本清单是 `novel-review` 的 L3 明细，规定三态判定的细则、证据引用格式与常见失败模式的定位方法。

## 一、三态判定细则

| 状态 | 成立条件 | 是否算通过 | 报告写法 |
|---|---|---|---|
| 通过 | 有可复现证据（门禁输出或章内定位）支撑，且未违反既定材料 | 是 | `[通过] 项目：证据` |
| 待改 | 命中既定阈值、或与既定材料（章纲/设定/状态）冲突 | 否 | `[待改] 项目：证据 + 位置` |
| 待核实 | 缺少判定所需材料，或证据不足以定性 | **否** | `[待核实] 项目：缺什么材料` |

硬性细则：

1. **待核实不算通过**。报告结论行必须单独给出待核实计数，不能并入通过。
2. 不能用「看起来没问题」「大致符合」把待核实项转写为通过。
3. 同一项既有命中又有待核实部分时，拆成两条分别标注。
4. 判定「待改」必须能指到具体阈值或具体材料，指不到就转「待核实」。

## 二、证据引用格式

统一两种，二者都要可复现：

- **门禁类**：`门禁名 + 字段 + 计数/位置`。例：`破折号 7 个（红线每 250 字 1 个），位置行 12、40、88`。
- **章内类**：`行号区间 + 原文摘句（≤20 字）`。例：`行 55-71，如「他想到那年的雨」`。

禁止作为证据的形式：

- 主观评价（「节奏拖沓」）——必须转成可定位的结构问题。
- 无位置的概括（「好几处都有问题」）——必须给全部位置或明确说明只抽样。
- 转述而非引用（「大概意思是主角很生气」）——要摘原句。

## 三、逐项检查内容

1. **字数门**：统计正文汉字（不含标点、空白），与本书区间比对；不足即待改，超上限仅提示。
2. **语言门**：HTML 标签/注释/实体一律阻断；外语 token 需有作者确认与精确登记记录，否则待改。
3. **禁词门**：禁用套话零命中；破折号与对话引号密度按门禁阈值判。
4. **去 AI 味门**：三连排比全禁；叙述层推测词零容忍；解释癖与升华腔提示位置。
5. **章节衔接**：开头是否复述上一章结尾（复述即待改）；结尾钩子是否有人回应。
6. **材料一致性**：与章纲、设定、状态是否冲突；冲突需要两边的定位证据。
7. **事实越界**：角色是否说出按「已知信息」栏不该知道的事。

## 四、常见失败模式与定位方法

| 失败模式 | 症状 | 定位方法 |
|---|---|---|
| 套话起句 | 段首密集出现「突然/缓缓」类词 | 按词表逐词检索，报计数与行号 |
| 破折号顶替停顿 | 叙述中破折号密集 | 统计密度，与阈值比对 |
| 对话不足 | 长段纯叙述无引号 | 计算对话引号密度 |
| 三连排比 | 「不是A，不是B，不是C」 | 按句式模式匹配，给行号 |
| 叙述层推测词 | 「似乎/显然/大概」出现在叙述句 | 区分叙述层与人物口语，只报叙述层 |
| 升华总结 | 章末出现「这一刻他明白了…」 | 检查末 3 段，报行号 |
| 开头复述 | 首段与前章末在讲同一场景 | 比对前章末尾与本章开头 |
| 钩子悬空 | 末尾抛出悬念但章内无铺垫 | 在章内检索钩子要素是否出现过 |
| 事实越界 | 角色掌握未告知的信息 | 对照角色「已知信息」栏与告知情节 |
| 情节越界 | 本章事件与章纲不符 | 逐条比对本章章纲情节点 |

## 五、报告模板

```
结论：通过 / 待改（N 项）/ 待核实（M 项）
[待改] 项目：证据（位置）
[通过] 项目：证据
[待核实] 项目：缺什么材料
建议下一步：…（不代写正文）
```
