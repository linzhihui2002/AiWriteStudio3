# 章节正文写作（novel-writing）

## 触发条件

- 作者要求写某一章、续写下一章、扩写某一段、重写整章。
- 章纲已定但正文为空，需要产出可入收件箱的草稿。

## 输入契约

- **章节合同**：本章情节点、字数预算、章末钩子类型、涉及实体。合同未冻结时先请作者生成并确认，不要自己拍。
- **必读集**：上一章末尾约 500 字（用于承上）＋ 角色状态卡（位置、伤势、随身物、已知信息）＋ 本章相关设定片段。
- **写作偏好**：本书的字数区间与门禁阈值来自工作台配置，不在本技能里硬编码。
- **目标路径**：新章为 `章节/第NNNN章.txt`，或作者指定的既有章节。
- 缺合同或缺必读集时，先索要，不要凭空开写。

写法细节（场景—动作—对话的展开方式、字数与门禁口径、章末收束）见 [章节写作规程](references/章节写作规程.md)。

## 输出契约

- **纯正文**：只有散文，不含标题行、不含创作说明、不含「以下是正文」这类引导语，不含 Markdown 标记。
- **语言**：简体中文散文。禁 HTML 标签与实体，禁外语字符泄漏。
- **落盘路径**：先进草稿区或收件箱，作者应用后才是正文；不得静默覆盖已有章节。
- **自检摘要**：交付时附一行自检结果：汉字数、门禁结论、章末钩子类型。

## 边界（做什么·不做什么）

**做**

- 按情节点顺序把本章写完，每段承担一个可识别的推进（动作、信息或关系变化）。
- 承接上一章的遗留点，让开头与上章结尾咬合。
- 章末落在合同指定的钩子类型上。

**不做**

- 不写章节标题、不写创作说明、不写摘要或目录。
- 不写大纲、不列细纲（归 novel-planning）。
- 不改设定与状态文件；需要新设定时在回复里提出，由作者另起一轮。
- 不泄露规划记号：情节点编号、字数预算、任务指令一律不得出现在正文里。
- 不提前消费后续章节的情节点。
- 不改动作者的合同内容；合同有问题时先提出来谈，而不是边写边改。

## 步骤

1. **核对合同**：读情节点、字数预算、钩子类型；确认上一章遗留点是什么（必须承上）。
2. **装配上下文**：把必读集需要的片段（上章末尾、状态卡、相关设定）读进来，只取相关部分。
3. **定开篇**：第一段直接进入场景或动作，不复述上一章结尾。
4. **推进**：按情节点顺序写，每段落一个推进；对话用于交换信息或暴露立场，不是填充篇幅。
5. **收束**：章末落在合同钩子上，不总结、不升华、不预告下一章标题。
6. **自检**：核对字数区间、门禁项、钩子一致性；不通过就改到通过为止。
7. **交付**：产物进草稿区与收件箱，不自动应用；附自检摘要。

### 判断规则

- **承上而不是复述**：开头可以提到上一章的结果，但不重复描写已写过的场景。
- **一段一推进**：写完一段自问「这段让什么发生了变化」，答不上来就删或合并。
- **有信息差的对话**：人物说话要带各自的立场和隐瞒，不要人人都把话说全。
- **字数**：以本书配置的区间为准，宁可在区间内写满，也不靠注水词凑数。
- **不确定就停**：情节点之间的矛盾先报告，不自行选一个继续写。

### 常见开工失败

| 现象 | 后果 | 处理 |
|---|---|---|
| 合同未冻结就开写 | 写完要整章重来 | 先请作者确认合同 |
| 必读集缺失（没读上章末尾） | 开头复述或断层 | 先补齐必读集再写 |
| 状态卡与实际不符 | 写出不可能的动作（带伤跑） | 报告冲突，等作者裁定 |
| 章纲情节点互相矛盾 | 无法落笔 | 停下来谈，不自行取舍 |

### 交付前自检动作

1. 汉字数用手数或门禁统计，不用「感觉差不多」。
2. 从头读一遍首段，确认没有复述上一章结尾。
3. 读最后三段，确认钩子是动作或事实，且与合同类型一致。
4. 全文检索规划记号（编号、「字数」「情节点」「合同」等词）。
5. 检查对话引号是否成对、是否有半角标点混入。

### 上下文装配清单

按下面顺序取材料，取不到就停：

1. **合同**：本章情节点、字数预算、钩子类型、涉及实体。
2. **上章末段**：约 500 字，用来承上。
3. **角色状态**：本章涉及角色的位置、伤势、随身物、已知信息。
4. **相关设定片段**：只取与本章人物、地点、道具相关的那几条，不整包拉进来。
5. **写作偏好**：本书字数区间与门禁阈值。

### 段落结构与推进自检

| 段落类型 | 作用 | 检查点 |
|---|---|---|
| 开场段 | 定场景与处境 | 是否进入动作，是否没复述上章 |
| 推进段 | 事件向前 | 是否让某一项状态发生变化 |
| 对话段 | 交换信息/立场 | 两人声音是否可分，是否有信息差 |
| 转折段 | 改变处境 | 转折是否有前置线索 |
| 收束段 | 落钩子 | 是否用动作或事实收尾，类型是否对 |

写完后逐段对照：任一段在表里找不到归属，就是多余段落。

### 交付摘要格式

```
本章：第0012章｜汉字 2410｜字数门通过｜禁词门通过｜钩子：行动型
产物：草稿区 → 收件箱（未应用）
存疑：第 3 情节点与前章状态卡的位置记录不一致，请作者裁定。
```

### 篇幅分配建议

以 2500 字一章为例：

| 部分 | 大致占比 | 作用 |
|---|---|---|
| 开场 | 10%-15% | 定场景、接上章 |
| 推进 | 45%-55% | 事件向前，含对话 |
| 转折 | 15%-20% | 处境改变 |
| 收束 | 10%-15% | 落钩子 |

开场与收束不要超过总量三成，否则中段会显得单薄。

### 与其他技能的衔接

- 章纲未冻结：先请 `novel-planning` 出章纲，不自己定情节。
- 需要新设定或状态更新：在回复里提出，由 `novel-setting` 另起一轮处理。
- 写完自审门禁不通过：语法类问题参照 `human-linguistics` 的手法改，不要靠增删情节凑数。
- 交付后由 `novel-review` 验收，写作者按报告修改，两侧不互相代劳。

### 常见退稿原因与预检

| 退稿原因 | 预检动作 |
|---|---|
| 汉字数不足 | 写完后统计一次，缺多少补一段有推进的内容 |
| 命中断句套话 | 通读首段与段首，删掉套话起句 |
| 破折号过多 | 逐段替换为句号或省略号 |
| 章末无钩子 | 读末三段，改成动作或事实收尾 |
| 开头复述上章 | 比对上一章末尾，删掉重复描写 |
| 泄漏规划记号 | 全文检索「情节点」「字数」「合同」等词 |

预检在交付前做一遍，比被退回后重写更省事。

### 定稿前的最后一遍读法

1. 只读每段第一句——能不能看出这段要干什么？看不出就是段落没有推进。
2. 只读所有对话——人物能不能区分开？区分不开就补称呼或句长差异。
3. 只读最后五段——钩子类型是否与合同一致？不一致按合同改。
4. 只读首段与上章末段——有没有重复描写的场景？有就删。
5. 全部读完后统计一次汉字数，落在区间内才算完成。

## 正反例

**反例 1（引导语与标题泄漏）**

> 以下是第 12 章的正文：\n\n第12章 夜航\n\n夜色如墨，浓稠得化不开……

问题：引导语、标题行、套话开篇，且「浓稠得化不开」是典型模型腔。

**正例 1**

> 沈砚把缆绳在桩子上绕了两圈，手背的旧伤被磨得发亮。「今夜潮水涨得早。」老周抬头看天。

开篇直接进入动作与对话，人物各说各的信息。

**反例 2（总结升华收尾）**

> 这一刻，他终于明白了坚持的意义。无论前路多么艰难，他都会走下去。

问题：替读者总结、点题升华，且没有钩子。

**正例 2**

> 他把货单折好塞进怀里，转身往官仓的方向走。身后的船灯一盏盏灭了。

落在动作与信息（他要去官仓）上，是合同指定的「行动型」钩子。

**反例 3（规划记号泄漏）**

> （情节点三已完成，字数 1800，接下来写情节点四）

问题：把规划记号写进正文。

**反例 4（复述上一章结尾）**

> 上一章说到，沈砚在码头等船，老周给了他一块饼。这一章继续。

问题：直接复述上章结尾，读者会跳读；正确做法是从新的动作切入。

**正例 4**

> 船没来。沈砚在桩子边坐到后半夜，饼还在怀里，硬得硌人。

提到饼但不复述上章场景，且直接推进（船没来 = 新变化）。

## 验收清单

- [ ] 合同情节点全部落地，逐项能在正文里找到证据。
- [ ] 汉字数落入本书配置区间，且通过字数门、语言门、禁词门、去 AI 味门。
- [ ] 正文无标题行、无引导语、无 Markdown 标记、无规划记号。
- [ ] 开头不复述上一章结尾，承上但不过渡复述。
- [ ] 章末钩子与合同一致，未提前消费后续情节点。
- [ ] 对话为中文引号且成对，人物有信息差与个性差异。
- [ ] 产物路径正确（草稿区 → 收件箱），未静默改写正文文件。
- [ ] 每段都有可识别的推进，删除了「无变化段」。
- [ ] 交付附自检摘要（汉字数、门禁结论、钩子类型）。
