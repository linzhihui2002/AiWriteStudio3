# 拆书对标（novel-teardown）

## 触发条件

- 作者指定一本参考作品（样章、全本或若干章），要求拆出可复用的写法。
- 作者问「这本书为什么好看」「前三章的钩子怎么做的」「它的节奏是怎么排的」。
- 写作前需要对标：作者给出同题材作品，要求提炼能迁移到本书的手法。
- 已拆目标需要补维度、补依据或重新召回（只读查看，不新增结论）。

本技能产出的是**对标资产**，不是本书书稿。参考作品与本书书稿是两类材料，不要混着写。

## 输入契约

开工前必须具备下面三样，缺一样先问，一次最多问 3 个问题，不要凭印象开拆：

1. **拆解目标**：参考作品的名称（对标书名）与待拆原文。原文缺失时先要原文，不要拿记忆里的印象替代原文；只拿到书名时明确说明「无原文无法取证」。
2. **题材标注**：这本书的题材（如悬疑 / 玄幻 / 都市 / 科幻）。题材是对标资产后续被召回的关键字段，缺省会导致召回失效；作者说不清时按原文特征给一个最可能的标注，并在资产里注明「题材待作者确认」。
3. **拆解范围**：拆全部还是只拆某几章。范围决定事实卡的章号口径，不要拆了一部分却按全本口径下结论。

字段级写法、维度定义、事实卡模板与召回口径见 [拆书维度与事实卡规范](references/拆书维度与事实卡规范.md)，按需读取，不要凭记忆编字段。

读取已有资产的入口：

- `list_teardown`（只读）：不带 `target` 时按 `genre` 召回已入库的事实卡，用来确认这本书是否已拆过；带 `target` 时列出该目标已入库的事实卡，用来续拆与查重。
- `read_file` / `list_files`：读取 `拆书/` 目录下已产出的 `拆解.md`、`双时间线.md`、`事实卡.md`，确认现有进度。

## 输出契约

每次拆解产出三份资产，落在该参考作品自己的目录下（由工作台服务写入，见 `workbench/backend/services/teardown_service.py`）：

- **`拆解.md`**：按六维分节的结论清单，每节先写该维关注点，再逐条给结论与依据。
- **`双时间线.md`**：事件时间线（故事内发生顺序）与揭示时间线（读者获知顺序）的对照表。
- **`事实卡.md`**：表格形式的事实卡，字段固定为「维度 / 结论 / 章节依据 / 原文摘录」。

输出纪律：

- **每条事实卡必须附章节依据**：写成 `第NNNN章` 加简短摘录（≤60 字）。取不到证据的条目一律标「依据缺失」，不补写、不编造、不拿「整体感觉」充数。
- **结账行**：末尾给出 `拆解 N 条 / 依据缺失 M 条 / 涉及章节 K 章 / 题材：X`，并单列依据缺失清单与缺哪一章补。
- **结论与原文分开**：摘录只保留能佐证结论的短句，不整段搬运参考作品原文。

## 边界（做什么·不做什么）

**做**

- 拆解参考作品，产出对标资产与事实卡。
- 把「这本书怎么写的」翻译成可复用的结构描述（章法、节拍、信息给法），而不是复述剧情。
- 指出本书可以直接借用的写法方向，并说明它对本书当前进度的意义。

**不做**

- 不写本书书稿：章节正文、设定、大纲、状态一律不动；需要据此改本书时，只在回复里提示「建议另起一轮处理」。
- 不改参考作品原文，不在参考作品目录里做任何写入。
- 不把参考作品内容原样复制进本书或资产正文；只给结构性描述与短摘录。
- 不越出六维自创维度；确需新增维度先报作者确认。
- 不做没有原文依据的判断，不把推测写成结论。

## 步骤

1. **确认目标与范围**：拿到书名、原文与题材，确认拆全本还是拆指定章节。缺原文就先要原文。
2. **查已拆进度**：用 `list_teardown` 按 `target` 列出已入库事实卡，避免重复拆同一本书的同一维度；已有资产先读再续。
3. **分章切分**：按原文的章节标记切章，记录每章字数与段数；切不出章号时按自然段区间给临时编号并注明「编号为工作台临时口径」。
4. **逐维取证**：按六维（开篇钩子、情绪节拍、主角行动线、信息节奏、语言特征、可迁移手法）逐条找证据，每找到一条就当场记下章号与短摘录，再写结论。**先有依据、后有结论**。
5. **写双时间线**：事件顺序按章节推进列；揭示顺序标出「读者何时比角色先知道」的错位点；错位点缺失时标「依据缺失」。
6. **分级来源**：给每条事实卡标来源级别（原文实证 / 统计口径 / 推测待核实），来源级别与依据一起落在资产里。
7. **出结账行**：统计条数、依据缺失数与涉及章节数，列出待补清单。
8. **给迁移建议**：把「可迁移手法」维度单独成节，每条写成「结构描述 + 适用条件」，不抄句子。

### 六维口径

| 维度 | 关注点 | 判不了时 |
|---|---|---|
| 开篇钩子 | 前 300 字做了什么、第几段给出冲突、用什么抓人 | 缺原文开头则记「依据缺失」 |
| 情绪节拍 | 每约 500 字一个可命名的节拍（爽/憋/惊/暖），节拍如何交替 | 无法命名节拍则只报区间长度 |
| 主角行动线 | 主角做了哪些决定、付出什么代价、目标如何升级 | 主角不明则转「待核实」 |
| 信息节奏 | 伏笔埋在哪、何时揭示、读者何时比角色先知道 | 无揭示点则记「依据缺失」 |
| 语言特征 | 句长分布、对话占比、口语化程度、标志性用词 | 样本不足则注明样本量 |
| 可迁移手法 | 能直接用于本书的写法，1–3 条，附可复制的结构 | 无可靠结论时宁可少给 |

维度定义以 `teardown_service.DIMENSIONS` 为唯一事实源；本表只是速查，实施时以服务实际产出口径为准。

### 事实卡纪律

1. 一条事实卡只讲一件事，结论一句话，能被原文验证。
2. 依据写到章号一级，不用「前几章」「中间部分」这类模糊指代。
3. 摘录短于 60 字，够佐证即可；超长摘录一律删到关键句。
4. 同一本书同一维度允许多条事实卡，但结论不得互相矛盾；冲突时两条都留，并在备注写清分歧。
5. 依据缺失的条目照样入库，标「依据缺失」而不是删掉，供作者判断要不要补拆。
6. 查重：入库前用 `list_teardown` 带 `target` 拉一遍，同维度同依据的条目合并，不重复堆卡片。

### 按题材召回的用法

对标资产的价值在于被写作时召回：写作前按本书题材召回同题材事实卡，注入的是结论与依据，不是原文。因此：

- 题材字段必须填，且尽量用工作台既有题材词，便于与本书题材做包含匹配。
- 召回只取**有章节依据**的条目，依据缺失条目仅供人工查看，不进上下文。
- 召回条数有限（默认少量几条），因此「可迁移手法」与「开篇钩子」两维优先写扎实，其余维度可少而精。

### 双时间线的双口径

- **事件时间线**：故事内事件发生顺序，按章节顺序列，允许跨章事件标出跨度。
- **揭示时间线**：读者获知顺序，重点标「读者先知道」的段落，这类段落是悬念与反转的设计位置。
- 两条线错位处就是作者真正要偷的手法；错位点拿不出来时说明「本轮样本不足」。

### 拆解顺序与范围选择

- **先切章，再逐维**：不要一边读一边下结论，先把章节边界与字数统计固定下来，之后所有依据都挂在这套章号上，避免同一本书两轮拆解章号口径不一致。
- **范围诚实**：只拆了前三章就写「本轮样本覆盖前三章」，不要用局部样本下全本结论；全本拆解时也允许分轮推进，分轮时在结账行写明本轮覆盖区间与下一轮起点。
- **顺序固定**：开篇钩子 → 情绪节拍 → 主角行动线 → 信息节奏 → 语言特征 → 可迁移手法。前两维决定这本书值不值得继续拆，后四维才是可迁移的部分。
- **一轮一目标**：一次只拆一本参考作品，不要把两本书的事实卡混在一份资产里；多本对标各自建目录，靠题材字段在召回时被一起选中。

### 与其他技能的协作

- 拆出的可迁移手法若要落到本书，交 `novel-planning`（结构层面）或 `novel-writing`（笔法层面）另起一轮执行，本技能不代写。
- 对标结论与本书现状的冲突（如本书节奏与对标手法不匹配）只在回复里指出，由作者裁定，不擅自改本书材料。
- 召回注入后由写作类技能消费；本技能不负责注入，只负责把资产写准、写全、可被召回。

### 资产落点与写入纪律

- 三份资产落在该参考作品自己的目录下，路径与文件名由工作台服务统一生成，不要手工另起文件名。
- 重新拆解同一目标会覆盖该目标的资产，因此续拆前先读旧资产，确认要保留的条目已在工作台内，再触发重拆。
- 资产内不出现本书的设定、大纲与正文片段；对标是单向引用，不把两本书的材料混写。

## 正反例

**反例 1（无依据下结论）**

> 结论：这本书的节奏很紧凑，每章都有爽点，值得学习。

问题：没有章号、没有节拍命名、没有依据，属于印象式评论，应按六维逐条取证后重写。

**正例 1**

> [情绪节拍] 结论：每章一个「憋—爽」短节拍，爽点落在章末。依据：第0003章、第0004章章末。
> 章节依据：第0004章「他把账本推回去，报出了另一个数」。

**反例 2（搬运原文）**

> 事实卡里整段粘贴参考作品第一章的原文，再写「这段写得好」。

问题：既无结论也无维度定位，还把参考作品内容搬进本书资产；应改为「结论 + 章号 + ≤60 字摘录」。

**正例 2**

> [开篇钩子] 结论：第 2 段给出利益冲突，用一句反问收尾。依据：第0001章。

**反例 3（越界改本书）**

拆完就顺手把本书 `设定/` 或 `大纲/` 改了，说「照着对标补一下」。

问题：越界。拆书只产出对标资产；本书材料要改，提示作者另起一轮，由对应 Agent 执行。

**反例 4（把待核实写成结论）**

> 结论：作者在后半本埋了三条暗线，最后都收了。

问题：没有章号依据，也没法验证「三条」这个数，应标「依据缺失」或降级为「推测待核实」。

**正例 4**

> [信息节奏] 结论：本轮样本只覆盖前三章，仅能确认 1 处埋设点。依据：第0002章。
> 结账行：拆解 6 条 / 依据缺失 2 条 / 涉及章节 3 章 / 题材：悬疑。

## 验收清单

- [ ] 拆解目标、原文与题材均已具备，缺失项已先问作者而非猜测。
- [ ] 六维齐备，或缺失维度已写明「依据缺失 / 本轮未产出」。
- [ ] 每条事实卡都带章节依据（章号 + ≤60 字摘录），无依据条目已标注。
- [ ] `拆解.md`、`双时间线.md`、`事实卡.md` 三份资产齐备，字段与模板一致。
- [ ] 双时间线区分事件顺序与揭示顺序，错位点或样本不足已说明。
- [ ] 来源分级已标注，推测条目未被写成结论。
- [ ] 未改动本书任何材料，也未改动参考作品原文。
- [ ] 摘录均为短句，未整段搬运参考作品内容。
- [ ] 已用 `list_teardown` 查重，未重复堆同维度同依据的卡片。
- [ ] 结账行给出条数、依据缺失数、涉及章节数与题材。
