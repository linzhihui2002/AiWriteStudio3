# 拆书维度与事实卡规范

本清单是 `novel-teardown` 的 L3 明细，规定六维拆解维度的定义与关注点、事实卡字段与章节依据写法、来源分级、按题材召回的口径，以及双时间线的记法。实施口径以 `workbench/backend/services/teardown_service.py` 的 `DIMENSIONS` 与其产出模板为唯一事实源。

## 一、六维定义（工作台自定）

| 维度 | 关注点 | 可用依据的形式 |
|---|---|---|
| 开篇钩子 | 前 300 字做了什么、第几段给出冲突、用什么抓人 | 段号 + 短摘录 |
| 情绪节拍 | 每约 500 字一个可命名的节拍（爽 / 憋 / 惊 / 暖），节拍如何交替 | 节拍名 + 区间章段 |
| 主角行动线 | 主角做了哪些决定、付出什么代价、目标如何升级 | 决定 + 代价 + 章号 |
| 信息节奏 | 伏笔埋在哪、何时揭示、读者何时比角色先知道 | 埋设章 / 揭示章 |
| 语言特征 | 句长分布、对话占比、口语化程度、标志性用词 | 统计值或章内例证 |
| 可迁移手法 | 能直接用于本书的写法，1–3 条，附可复制的结构而非句子 | 结构描述 + 适用条件 |

维度是工作台自定的固定六项，不随书变化。拆不出结论的维度保留并标「依据缺失」，不要删维度、不要自创第七维；确需新增维度时先报作者确认，再统一改口径。

## 二、事实卡字段与章节依据

事实卡字段固定四项，不增不减：

| 字段 | 必填 | 说明 |
|---|---|---|
| 维度 | 是 | 六维之一，取值须与上表完全一致 |
| 结论 | 是 | 一句话说清「这本书在这维上做了什么」，能被原文验证 |
| 章节依据 | 是 | 章号到章节一级，如 `第0004章`；跨章写 `第0012-0014章` |
| 原文摘录 | 否 | ≤60 字的短句，仅用于佐证，不整段搬运 |

**章节依据是硬要求**：

1. 每条事实卡至少一个章号；取不到章号就不能写结论，改标「依据缺失」。
2. 禁止用「前几章」「中间部分」「全书」这类模糊指代当依据。
3. 摘录必须与结论对应；结论说「反问收尾」，摘录就要是那句反问。
4. 依据缺失的条目照样保留在 `事实卡.md` 里，标「依据缺失」，供作者决定是否补拆。
5. 同维度同依据的条目入库前合并，不重复堆卡片。

## 三、来源分级

每条事实卡给一个来源级别，写进结论行或备注：

- **原文实证**：能在原文找到具体章号与摘录，最可信，可进召回。
- **统计口径**：由分章统计得到（字数、段数、句长均值、对话占比），可复核但不含语义判断。
- **推测待核实**：依据薄弱或样本不足，只作线索，不进召回，需作者或后续拆解确认。

分级的用途是让召回与人工查看分开：召回只取**原文实证**且章节依据非空、非「依据缺失」的条目。

## 四、按题材召回的口径

召回是在写作时把同题材的对标结论注入上下文，因此题材字段决定资产是否被用上。

- 题材标注尽量用工作台既有题材词（本书题材与对标题材做包含匹配即命中）。
- 本书未填题材时，任何题材的对标事实都可能被召回；此时更要把结论写准，避免误导。
- 召回条数有限，排序上优先「可迁移手法」与「开篇钩子」，因此这两维要写扎实。
- 依据缺失的条目只供人工查看，不进召回。
- 召回注入的是结论与依据，不是参考作品原文；不要靠长摘录来「让模型自己看」。

## 五、双时间线记法

- **事件时间线**：故事内事件发生顺序，按章节顺序列表，列为章号、字数、段数、句长均值、对话占比、首句。
- **揭示时间线**：读者获知顺序，重点标读者先于角色知道的段落；这类段落是悬念与反转的设计位置。
- 两条线的错位处是最值得偷的写法；错位点取不出来时写「本轮样本不足」，不要硬编。

## 六、常见失败模式

| 现象 | 问题 | 修法 |
|---|---|---|
| 结论无章号 | 无法复核 | 补章号与摘录，补不到就标「依据缺失」 |
| 摘录过长 | 变相搬运 | 删到 ≤60 字关键句 |
| 维度缺项 | 资产不齐 | 缺失维度保留并标注，不删 |
| 题材留空 | 召回失效 | 补齐题材或注明待确认 |
| 推测当结论 | 误导读作 | 降级为「推测待核实」，不进召回 |
| 顺手改本书 | 越界 | 只产出对标资产，本书材料另起一轮 |
