# 设定与状态维护（novel-setting）

## 触发条件

- 作者要求新增或修改某张设定卡：人物、势力、世界规则、物品、技能、场景、伏笔。
- 正文里出现了设定里查不到的名词（人名、地名、组织、功法），需要决定「补卡」还是「改词」。
- 需要结转上一章的状态：时间推进、角色位置与伤势、心理与关系、资源进出、伏笔回收。
- 作者说「账对不上」「时间线乱了」「这个设定前后打架」。
- 写作前只想把某条设定查清楚（只读，不写盘）。

## 输入契约

### 文档呈现约定

- 一张设定对应一个真实对象，标题使用对象名称；「姓名、身份、来源」等是对象字段，不另建对象标题。
- 设定与当前状态采用对象标题加分行字段，字段名可加粗，字段值用普通正文；需要对照时使用标准 Markdown 表格，表头与分隔行齐全。
- 字段来源规范放在字段行末，如 `- 性质：神秘组织。（来源：author）`；未知值用「待确认」，不在长自然段反复插入英文来源标记。
- 保留 author/model/unknown 与原文依据；来源不等于确认状态。作者提供但未拍板的内容仍明确写「待确认」。
- 时间线、资源账本、伏笔流水继续遵循既有追踪格式，不为展示效果改写流水结构；颜色及字数提示由工作台显示层生成，不写进正文。
- 工作台设定卡由作者手动触发 AI 从现有材料提取。不要把卡片解析当作生成新事实或补全未知值的授权。

开工前必须具备三样，缺一样就先问，不要猜：

1. **目标材料**：本次要动的具体文件（`设定/…` 或 `状态/…`）。作者说「把设定补一补」时，先确认改的是哪一类，一次最多问 3 个问题。
2. **章节依据**：变更对应的章号或路径，外加原文摘句。拿不到依据的变更只能登记为「待核实」，不得写盘。
3. **现有条目**：改动已有条目时，必须先读出旧条目原文，用于旧值校验；状态类提案要逐字报出旧值。

字段级的写法见 [设定字段规范](references/设定字段规范.md)；四件套的字段与追加规则见 [状态维护细则](references/状态维护细则.md)。这两份清单按需读取，不要凭记忆编字段。

## 输出契约

- **静态设定**（`设定/`）：给出可直接粘贴的条目块，字段齐全，每个字段带来源分级 `author` / `model` / `unknown`。
- **动态状态**（`状态/`）：时间线、资源账本、伏笔台账按追加规则产出新行；角色状态变更一律以提案提交，附旧值与新值。
- **结账行**：每次输出末尾给出 `新增 N 条 / 修改 M 条 / 待核实 K 条 / 去向：…`，并单列待核实清单与缺什么材料。
- **冲突块**：发现矛盾时单独列出「冲突：设定说 X（依据章 A），正文说 Y（依据章 B）」，再给可选走法。

## 边界（做什么·不做什么）

**做**

- 维护设定卡与状态四件套。
- 把正文与设定的冲突显式暴露，给出两种取舍，由作者决定。
- 把无法判定的条目标成「待核实」，并写清缺的材料。

**不做**

- 不写章节正文（归 novel-writing）。
- 不列也不改大纲、章纲（归 novel-planning）。
- 不动 `章节/` 下的文件。
- 不把正文与设定的冲突「顺手抹平」，也不在两个说法之间自行选一个。
- 不把 `unknown` 来源的字段当既定事实使用；引用时必须标注它是待核实的。
- 不在同一轮里顺带改其他材料。发现连带需求（例如「顺便把章纲也改了吧」），在回复里说明「建议另起一轮处理」，交由路由决定执行者。

## 步骤

1. **读**：目标材料 ＋ 本次相关章节 ＋ 相关 `状态/` 文件（时间线、角色状态、资源账本、伏笔台账）。
2. **抽取**：列出出场角色、时间线索、状态变更、资源变动、伏笔埋设与回收、新出现的专有名词。
3. **定位依据**：给每条候选记录附章号与原文摘句；找不到依据的降级为「待核实」，本次不写盘。
4. **定来源**：作者明确给出的标 `author`；从正文提炼出来的标 `model`；无法判定的标 `unknown`。
5. **写入**：静态设定按字段填齐；动态状态按追加规则处理；角色状态变更走提案，旧值逐字对齐。
6. **结账**：报数量与去向，单列待核实清单，并标明下一轮建议补哪个材料。

### 判断规则

- **该不该建卡**：正文提到且后续还会复用的对象才建卡；一次性道具只进时间线，不单独建卡，避免设定目录膨胀。
- **粒度**：一张卡只描述一个对象。世界观总述、势力、人物分开建，不要把「世界如何运转」和「主角的性格」塞进同一张卡。
- **关系双向**：写「甲对乙的态度」时，检查是否需要同时补「乙对甲」这一条，别留下单边关系。
- **新旧冲突**：正文与设定不一致时，先原样报出两个说法及其依据，再给「改设定」与「改正文」两条路，不要自作主张。
- **数值只报不改**：账本算术不成立时，指出行号与差值，绝不顺手改数，改数会让后续所有章节对不上。
- **命名统一**：同一对象在全文只能有一个正式名，别名与旧称单独列在「别名」字段，检索时才找得到。
- **不写未来**：设定卡只描述「截至当前章已成立」的事实，计划中的设定写进「待定」小节并标注未确认，避免把设想当既成事实。

### 何时必须停下来问作者

出现下面任意一种，先问再写，不要带着猜测落盘：

- 同一个对象有两种互斥说法，且两种都能在正文里找到依据。
- 状态快照与本章正文冲突（例如状态说在城东，正文写他在码头）。
- 需要新增一类此前不存在的设定卡（例如全书第一次出现「功法等级」），数量与分类由作者定。
- 资源账本前值断链，且断链位置早于本次改动范围。
- 作者的要求牵动了另一类材料（大纲、正文），超出本轮范围。

### 按材料分派规则

| 抽取到的东西 | 该写去哪 | 写法 |
|---|---|---|
| 人物首次登场、身份与能力 | `设定/人物设定.md` | 建人物卡，字段齐全、写清能力上限 |
| 世界规则、势力冲突 | `设定/世界设定.md`、`设定/势力设定.md` | 建卡，写明代价与例外 |
| 新物品、新功法 | `设定/物品设定.md`、`设定/技能设定.md` | 写持有人与当前所在地 |
| 时间推进、地点转移 | `状态/时间线.md` | 追加新行，标故事内时间 |
| 位置、伤势、心理、关系 | `状态/角色状态.md` | 走提案更新当前值，附旧值 |
| 收入与支出 | `状态/资源账本.md` | 追加，算术必须自洽 |
| 新埋或回收的线 | `状态/伏笔台账.md` | 追加，状态用四值之一 |

抽取出来的东西对不上号时，不要硬塞进现有文件，先在报告里问作者该放哪一类，避免把设定目录搞乱。

### 一致性自查五问

1. 这张卡的每个字段，能否指到某一章的原文？
2. 同一对象在设定与正文里的正式名是否一致？
3. 新加的设定与既有规则是否冲突？冲突是否已报告而不是被磨平？
4. 状态快照的时间点，是否与时间线最后一行对得上？
5. 本轮是否只动了本轮声明的材料，没有顺手改别的？

### 交付格式示例

```
【新增】人物卡 1 张 → 设定/人物设定.md
  沈砚｜身份：据点跑货人（依据：第0003章 码头交货）
【修改】状态/角色状态.md（提案 #21，含旧值：位置=城东）
【待核实】2 条：① 货主身份（缺第0014章正文）② 铜印来历（正文仅一次提及）
结账：新增 1 条 / 修改 1 条 / 待核实 2 条 / 去向：设定、状态
```

待核实条目必须能从报告直接看出缺哪份材料，否则作者无从补件。

### 与其他技能的衔接

- 需要新大纲或改大纲：不在本轮处理，提示「建议另起一轮交给大纲规划」。
- 角色行为与角色卡冲突：把冲突写进报告，判定归 `character-arc`。
- 伏笔的回收状态判定：本技能只负责把呼应写进台账（标疑似），能否算回收由作者确认，检查流程归 `foreshadow-check`。
- 需要正文改写：只提出，不代写；正文归 `novel-writing`。

## 确定性校验（只报告不改写）

机械可判定的部分交给门禁跑，结论只进报告，绝不顺手改数改卡：

- **账本与条目 ID**：调用对话工具 `check_tracking`（`target="账本"`，默认校验 `状态/资源账本.md`），或直接跑 `gates/tracking_gate.py` 的 `run_ledger`（逐行核对「前值 ＋ 变动 ＝ 结余」，给出不满足的行号与差值）与 `run_ids`（条目 ID 唯一性与格式）；两者合并入口是 `tracking_gate.run`。解析不出来的行只列入 `unparsed`，不判失败。
- **设定卡字段**：`check_tracking`（`target="设定"`，必须给 `category`，如 `人物` / `世界` / `状态`）或 `gates/setting_gate.py` 的 `run`——必填字段缺失为 error，未标来源分级为 warn。
- 校验结论并入结账行（如「校验：3 行算术不符、1 个 ID 重复」），并提醒作者这是待核实项。

## 正反例

**反例 1（不可验证）**

> 沈砚是个沉默寡言、剑术高强的年轻人。

问题：无章节依据、无来源分级、形容词无法被后续章节校验，也没写他强到什么程度。

**正例 1**

> 沈砚｜身份：据点跑货人（依据：第0003章 码头交货）｜目标：攒够三十两赎身（第0005章 自语）｜动机：妹妹被质押（第0009章 与老周对话）｜能力边界：短刀熟练，打不过练气三层（第0007章 被压制）｜语言习惯：短句、少用敬称（第0002、0009章）｜已知信息边界：不知道货主是谁（第0009章）｜来源：model

**反例 2（算术不可校验）**

> 第0012章：结余 30 两。

问题：没有前值与变动，后面任何一章都无法验证。

**正例 2**

> 第0012章｜前值 12 两 ＋ 收货款 18 两 － 购麻绳 0 两 ＝ 结余 30 两（依据：第0012章 交货段）

**反例 3（越界）**

作者说「完善一下设定」，执行时顺手把 `大纲/章纲.md` 的章号也改了。

问题：越出本轮材料范围。正确做法是只改设定，并在回复里提示「章纲需要另起一轮」。

**反例 4（把设想当事实）**

> 沈砚的身世：他是前朝遗孤，将在第七卷揭晓。

问题：这是作者的设想而非已成立的事实，应当写进「待定」小节并标注未确认，不能混在已成立字段里。

**正例 4**

> 待定（未确认）：沈砚身世线索留待后续，作者尚未决定（来源：author 提及但未拍板）。

## 验收清单

- [ ] 每条新增记录附章节依据；无依据的标「待核实」，没有伪装成已确认。
- [ ] 每个设定字段标注来源分级（author / model / unknown）。
- [ ] 角色状态变更以提案形式提交，未静默写盘，提案含旧值且与台账逐字一致。
- [ ] 资源账本每行满足「前值 ＋ 变动 ＝ 结余」；不满足的只报不改。
- [ ] 设定与正文的冲突已显式指出，并给出两种取舍。
- [ ] 未越界改大纲、章纲与章节正文。
- [ ] 结账行完整：新增/修改/待核实数量与去向齐全。
- [ ] 待定设想单独成节并标注未确认，未混入已成立字段。
- [ ] 同一对象只有一个正式名，别名已登记在别名字段。
