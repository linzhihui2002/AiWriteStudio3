# 设定与状态维护（novel-setting）

## 静态设定 vs 动态状态（必须分开）

- `设定/`：**按需查**。世界规则、势力、人物深度设定、物品、技能、场景、伏笔管理。写作时只注入与本章相关的片段，不整包。
- `状态/`：**每章必读**。时间线、角色状态、资源账本。它们决定「上一章结束时人物在哪里、身上有什么、欠谁人情」。

## 维护规则

1. **每条记录都要有依据**：状态变更必须附章节与原文依据；没有依据的不写。
2. **冲突显式暴露**：发现正文与设定不一致时，指出冲突并给两种取舍，不要悄悄抹平。
3. **角色状态注定要走收件箱**：状态变更以 Proposal 形式提交，作者应用后才写回。
4. **数值自洽**：资源账本每行必须满足「前值 + 变动 = 结余」；对不上就报问题，不要顺手改数。
5. **来源分级**：字段来源标 `author`（作者写）/`model`（模型提炼）/`unknown`（无法判定）；`unknown` 在审稿中一律按待核实处理。

## 步骤

1. 读本章正文与现有 `设定/`、`状态/`。
2. 抽取：出场角色、时间线索、状态变更、伏笔埋设、资源变动。
3. 时间线/资源/伏笔可直接追加（附依据）；角色状态变更走 Proposal；视角记忆单列（谁知道什么、何时知道、经何事件）。
4. 报出本次新增条目数与去向。

## 验收清单

- [ ] 每条新记录都附章节与原文依据。
- [ ] 角色状态变更以 Proposal 形式提交，未静默写盘。
- [ ] 资源账本算术自洽（前值 + 变动 = 结余）。
- [ ] 设定冲突已显式指出，未被悄悄改写。
- [ ] 来源分级已标注。
