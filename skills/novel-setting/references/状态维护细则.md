# 状态维护细则

本清单是 `novel-setting` 的 L3 明细，规定 `状态/` 下四件套的字段与**追加规则**。四件套每章必读，写错会连锁污染后面所有章节，因此规则要严于静态设定。

## 总则

- **只追加，不覆盖**：时间线、资源账本、伏笔台账都是流水账，新事实追加新行，旧行保留。
- **每行可校验**：一行记录必须能独立读出「谁、何时、依据什么」。
- **角色状态例外**：`状态/角色状态.md` 是当前值快照，需要覆盖更新，因此必须走提案，不能直接改写。

## 时间线（`状态/时间线.md`）

每行字段：

```
第NNNN章 ｜ 故事内时间 ｜ 地点 ｜ 事件 ｜ 涉及角色 ｜ 依据
```

追加规则：

1. 故事内时间尽量给可比较的量度（第几日/第几月，或「交货次日」这类相对锚点）。
2. 新行时间早于上一行时，说明是倒叙还是补记，避免时间线看起来倒流。
3. 同一章多件事就多行，不要压成一行把地点和人物混在一起。
4. 依据写章节号加简短定位，不抄原文。

## 角色状态（`状态/角色状态.md`）

当前值快照，字段：

- 位置、伤势与体力、当前心理、随身物、对外关系值、缺口（欠谁的、被谁盯上）、最后更新章。

更新规则：

1. **走提案**：变更以提案提交，附旧值原文，作者应用后才生效。
2. **只写可观测项**：「心理」只写有正文支撑的状态（「因妹妹被质押而急躁」），不写作者的判断。
3. **关系变化要有铺垫章**：关系值发生方向变化时，必须指出铺垫章；找不到铺垫就标「无铺垫突变」，交给角色弧光检查。
4. **视角记忆单列**：另起「已知信息」小节，写清谁知道什么、何时知道、经由什么事件。这栏是防事实越界的关键，不要省。

## 资源账本（`状态/资源账本.md`）

每行字段：

```
第NNNN章 ｜ 项目 ｜ 前值 ＋ 变动 ＝ 结余 ｜ 依据
```

校验规则：

1. 算术必须成立，逐行可验；一行一条资源流水，不要把两种资源写在一行。
2. 前值必须等于上一行同项目的结余；对不上就报「前值断链」，指出上一行行号。
3. 变动为负时用减号并写明用途，不要只写「支出」。
4. 校验失败**只报不改**：给出不满足的行号与差值，交给作者或修正正文。

## 伏笔台账（`状态/伏笔台账.md`）

每行字段：

```
伏笔ID ｜ 内容 ｜ 埋设章 ｜ 依据原文 ｜ 回收状态 ｜ 计划回收章 ｜ 备注
```

状态取值只允许四种：`待回收`、`疑似回收`、`已回收`、`作废`。

追加与更新规则：

1. **新增**：埋设伏笔时追加行，ID 唯一且不复用。
2. **疑似回收**：正文出现呼应时标「疑似回收」并附呼应章；**能否升级为「已回收」只能由作者确认**，工具不得自行判定。
3. **作废**：必须写明作废代价（这个坑不填会留下什么观感问题）。
4. **查重**：追加前先按内容检索台账，同一件事重复埋设要合并或说明差异。
5. 详细检查流程见 `foreshadow-check` 技能，两边口径必须一致。

## 常见失败模式

| 现象 | 后果 | 处理 |
|---|---|---|
| 直接覆盖旧行 | 丢失历史，无法回溯 | 追加新行，旧行保留 |
| 账本只写结余 | 无法校验 | 补前值与变动 |
| 关系值突变无铺垫 | 角色崩坏 | 标「无铺垫突变」，指出应补铺垫的章 |
| 视角记忆缺失 | 角色说出不该知道的事 | 补齐「已知信息」栏 |
| 来源 long-term 挂 unknown | 待核实项被当事实 | 拿到依据后立即升级来源 |
