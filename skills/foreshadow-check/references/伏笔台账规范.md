# 伏笔台账规范

本清单是 `foreshadow-check` 的 L3 明细，规定 `状态/伏笔台账.md` 的字段、状态取值、追加与更新规则，以及四类检查的判定口径。

## 一、字段定义

| 字段 | 必填 | 说明 |
|---|---|---|
| 伏笔ID | 是 | 唯一且不复用，如 `FS-014` |
| 内容 | 是 | 一句话说清「埋了什么」，要能被正文验证 |
| 埋设章 | 是 | `第NNNN章`；跨章埋设时填首次出现的章 |
| 依据原文 | 是 | 简短摘句（≤20 字），不抄整段 |
| 回收状态 | 是 | 四值之一，见下 |
| 计划回收章 | 否 | 有计划的填章节窗口，如 `第0051-0053章` |
| 备注 | 否 | 作废代价、重复埋设说明等 |

## 二、回收状态取值

只允许四种，不得自创：

- `待回收`：已埋设，尚无呼应。
- `疑似回收`：正文出现呼应，但可能是巧合或另有所指。
- `已回收`：**只能由作者确认后标注**。
- `作废`：作者明确放弃，必须写明作废代价。

## 三、追加与更新规则

1. **新增**：埋设伏笔时追加行；ID 递增，不复用已删条目的 ID。
2. **呼应出现**：追加或更新为 `疑似回收`，并在备注写呼应章号与摘句。
3. **升级**：`疑似回收 → 已回收` 必须由作者确认，工具只提建议。
4. **作废**：写明代价（这条线不填会留下什么观感问题）。
5. **查重**：新增前按内容检索台账与正文，同一件事重复埋设要合并或说明差异。

## 四、四类检查的判定口径

### 1. 超期未回收

- 条件：`待回收` 且（当前已写章节号 − 埋设章号）> 约定章数（默认 20）。
- 输出：给两个选项——本卷内的具体回收窗口，或作废并给代价。
- 注意：跨越卷的伏笔可放宽，但必须在备注里写明计划回收卷。

### 2. 回收无铺垫

- 条件：判为 `已回收` 或 `疑似回收`，但回收章前 3 章内无任何呼应痕迹。
- 输出：指出应在哪一章补铺垫，补什么（回扣物件、人物提一句、环境呼应）。

### 3. 重复埋设

- 条件：同一件事被埋两次以上，且两次之间没有递进关系。
- 输出：建议合并为一条（保留更早的埋设章）或把第二次改写为明确呼应。

### 4. 悬空指涉

- 条件：正文出现「此前埋过的东西」的指涉，但台账中无对应条目。
- 输出：列出章号与摘句，请作者决定是补登台账，还是改掉正文中的指涉。

## 五、报告字段与结账行

报告每行固定：

```
伏笔内容 ｜ 埋设章 ｜ 当前状态 ｜ 问题类型 ｜ 依据原文 ｜ 建议动作
```

结账行格式：

```
待回收 N 条 / 疑似回收 M 条 / 已回收 K 条 / 作废 J 条；其中超期 X 条
```

## 六、常见失败模式

| 现象 | 问题 | 修法 |
|---|---|---|
| 凭相似关键词判回收 | 误判 | 必须有正文呼应证据 |
| 直接改状态 | 越权 | 只提建议，作者确认后走提案 |
| 超期项只报不给出路 | 无行动 | 必须给回收窗口或作废代价 |
| 台账缺 ID 或 ID 复用 | 无法追溯 | 统一递增，不复用 |
| 备注缺失 | 后续无法判断 | 呼应章、代价、放宽理由都要记 |
