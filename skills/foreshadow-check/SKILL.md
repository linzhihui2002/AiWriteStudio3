# 伏笔检查（foreshadow-check）

## 台账口径

每条伏笔记录必须包含：内容、埋设章、依据原文、回收状态（待回收/疑似回收/已回收/作废）、计划回收章。
**回收状态只能由作者确认**——工具只能标「疑似回收」（正文里出现了呼应，但可能只是巧合）。

## 检查项

1. **超期未回收**：已埋设超过 N 章（默认 20 章）仍在「待回收」。
2. **回收无铺垫**：判定为已回收，但回收前 3 章内没有任何呼应痕迹。
3. **重复埋设**：同一件事被重复埋两次（读者会觉得啰嗦）。
4. **悬空指涉**：正文提到某个「此前埋的东西」，但台账里查不到对应条目。

## 步骤

1. 读 `设定/伏笔管理.md` 与全部章节正文（可用本地检索定位关键词）。
2. 对每条伏笔做上述四项检查，输出清单：伏笔内容 / 埋设章 / 状态 / 问题类型 / 依据原文 / 建议动作。
3. 对「超期未回收」给出两个选项：本卷内回收（给具体章节窗口）或作废（并说明作废的代价）。
4. 需要作者确认的动作一律走收件箱或人工确认，不自动改台账。

## 验收清单

- [ ] 每条结论都有章节依据或原文摘录；查不到依据的写「依据缺失」。
- [ ] 未把「疑似回收」直接当成「已回收」。
- [ ] 超期伏笔给出明确的回收窗口或作废建议。
- [ ] 未自动修改 `设定/伏笔管理.md` 的回收状态。
