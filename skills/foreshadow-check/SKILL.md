# 伏笔检查（foreshadow-check）

## 触发条件

- 作者要求盘点伏笔的埋设与回收状态。
- 一卷收尾前需要确认哪些线必须在本卷回收。
- 正文读起来有「提到过但没交代」的地方，需要核对台账。

## 输入契约

- **伏笔台账**：`状态/伏笔台账.md`（只读，不直接改）。
- **正文覆盖面**：本次要核对到第几章；不指定时按台账中已埋设的最晚章往前核对。
- **判定依据**：正文原文用来确认「是否出现呼应」，台账字段格式见 [伏笔台账规范](references/伏笔台账规范.md)。
- 台账缺失时：先报告「无台账可核对」，并从正文里抽取候选伏笔列出，交作者确认后再建账。

## 输出契约

- **清单**：每条伏笔一行，字段为 `伏笔内容 / 埋设章 / 当前状态 / 问题类型 / 依据原文 / 建议动作`。
- **分级结论**：把问题分成四类——超期未回收、回收无铺垫、重复埋设、悬空指涉。
- **建议动作**：对超期伏笔给两个选项（本卷内回收的具体章节窗口，或作废并说明代价）。
- **结账行**：`待回收 N 条 / 疑似回收 M 条 / 已回收 K 条 / 作废 J 条`。

## 边界（做什么·不做什么）

**做**

- 逐条核对状态，指出问题与依据。
- 从正文中检出未被登记的候选伏笔，交作者确认。
- 给出回收窗口与铺垫位置的建议。

**不做**

- 不改 `状态/伏笔台账.md`，尤其**不自行把「疑似回收」改成「已回收」**。
- 不写正文、不列大纲、不改设定。
- 不凭标题或关键词相似就判定回收，必须有正文呼应证据。
- 不因「作者可能记得」而放弃标注超期项。

## 步骤

1. **读台账与正文**：拿到台账全部条目，并覆盖到指定章节范围的正文。
2. **逐条核对**：对每条伏笔定位埋设章依据，并在正文里检索是否出现呼应。
3. **问题归类**：按四类问题给每条打标签，交叉的条目分行标注。
4. **抽取漏登**：正文里出现「此前埋过的东西」但台账没有的，列为悬空指涉候选。
5. **给建议**：超期项给回收窗口或作废建议；回收无铺垫项指出应在哪一章补铺垫。
6. **出清单与结账行**：等作者确认后再谈台账更新（更新走提案）。

### 判断规则

- **状态只能标到「疑似回收」**：正文出现呼应就标疑似；升级为「已回收」必须由作者确认。
- **超期口径**：埋设后超过约定章数（默认 20 章）仍为待回收即算超期；约定章数按本书配置取。
- **铺垫窗口**：判定「回收无铺垫」时，检查回收章前 3 章内有无呼应痕迹。
- **只报告不改**：任何需要改动台账的动作都写成建议，由作者或后续提案执行。
- **证据缺失照实写**：查不到埋设依据的条目写「依据缺失」，不要跳过。
- **区分主线与支线**：同一批超期伏笔里，与主线冲突相关的优先回收，纯氛围性的可作废，报告里按优先级排序。
- **跨卷伏笔放宽但不放过**：跨越两卷以上的伏笔，超期判定可放宽，但必须在备注里写明计划回收卷，否则仍按超期报出。

### 检查范围与优先级

1. **范围**：默认核对台账中全部未结条目，正文覆盖到作者指定章；未指定时覆盖到最新已写章。
2. **排序**：先报超期未回收（按超期章数降序），再报回收无铺垫，再报重复埋设，最后报悬空指涉。
3. **抽样禁止**：正文检索不得只扫最近几章；至少覆盖每条伏笔埋设章之后的全部章节。
4. **台账缺失时**：先从正文抽取候选伏笔（出现两次以上、且未在当章交代的线索），列出候选清单交作者确认是否建账，不做状态判定。

### 四类问题的判定速查

| 问题类型 | 判定条件 | 输出要求 |
|---|---|---|
| 超期未回收 | 待回收 且 已过 > 约定章数（默认 20） | 给回收窗口或作废代价 |
| 回收无铺垫 | 已/疑似回收，但回收章前 3 章无呼应 | 指出补铺垫的章与补法 |
| 重复埋设 | 同一事被埋 ≥2 次且无递进 | 建议合并或改写为呼应 |
| 悬空指涉 | 正文指涉前人前事，台账无对应条目 | 给章号与摘句，请作者裁定 |

### 逐条核对的操作顺序

1. 从台账取出全部未结条目，按埋设章排序。
2. 对每条在正文里检索关键词（名称、物件、动作），记录命中的章号与摘句。
3. 有呼应且能确认是同一件事的，标「疑似回收」；只是同名的标注「疑似同名，不计入回收」。
4. 无呼应的按超期口径判断；超期的排进优先处理清单。
5. 单条伏笔处理完立刻写一行报告，不要等全部查完再回忆。

### 建议动作的写法

- **回收窗口**：给出连续 2-3 章的范围，并说明在这几章里怎么回收（回扣物件、人物点破、场景重现）。
- **作废**：必须写代价（例如「失去老周与主角的绑定，后续第三卷的背叛动机需要另找理由」）。
- **补铺垫**：指出应在哪一章补什么（一次观察、一句对话、一个物件的再次出现）。

### 报告示例

```
结论：超期 2 条、回收无铺垫 1 条、悬空指涉 1 条
[超期] 老周的欠条｜埋设 第0009章｜已过 34 章｜建议：第0051-0053章回收，或作废（代价：老周线失去绑定）
[超期] 铜印来历｜埋设 第0012章｜已过 31 章｜建议：本卷末回收
[回收无铺垫] 船老大之子｜第0044章判为回收｜回收前 3 章无呼应｜建议：第0041章补一次提及
[悬空指涉] 第0038章「他想起那人说过的话」｜台账无「那人」｜请作者裁定
结账：待回收 5 条 / 疑似回收 2 条 / 已回收 3 条 / 作废 1 条；其中超期 2 条
```

### 与其他技能的衔接

- 台账字段与追加规则由 `novel-setting` 的《状态维护细则》规定；本技能只读不写，以该细则的口径为准。
- 本次判定若要改动台账，写成建议并说明理由，落地由设定类流程走提案。
- 「回收无铺垫」若本质是角色说了不该知道的事，转 `character-arc` 判事实越界。
- 需要删改正文指涉时，只提建议，正文归 `novel-writing`。

### 交付前自查

1. 每条结论是否都能落到台账某一行或正文某一句？
2. 有没有把「疑似回收」写成「已回收」的措辞？
3. 超期条目是否都给了出路（窗口或作废）？
4. 报告里是否出现了「已修改台账」这类越权表述？
5. 结账行的四个计数是否与清单行数对得上？

### 判定用语规范

- 可以写：「疑似回收」「建议回收窗口为第 0051-0053 章」「请作者确认是否算回收」。
- 不得写：「已回收」「已更新台账」「我把它标成作废了」。
- 状态词一律带引号，避免报告读起来像已经在改文件。
- 结论里出现「建议」「请作者」是正常的，出现「已」加动词（已改、已删、已标）一律是越权表述，需删掉重写。
- 报告中每条建议都要说明依据，不写无出处的主张。

## 确定性校验（只报告不改写）

台账里可机械判定的部分交给门禁跑，用来给「依据缺失」「待核实」提供硬证据，不代替逐条正文核对：

- **条目 ID 唯一性**：调用对话工具 `check_tracking`（`target="账本"`），或 `gates/tracking_gate.py` 的 `run_ids`——ID 重复、缺分隔符、编号超长一律进 `findings`；只报不改，尤其不自行改 ID。
- **伏笔卡字段与来源分级**：`check_tracking`（`target="设定"`, `category="伏笔"`）或 `gates/setting_gate.py` 的 `run`——缺必填字段为 error，未标来源分级为 warn，可据此判「依据缺失」。
- 校验结论并入结账行，并说明仍有 `M` 条靠正文证据判断。

## 正反例

**反例 1（越权升级状态）**

> 第0031章出现「旧钥匙」，判定该伏笔已回收。

问题：工具无权把状态改成「已回收」，且仅凭物件重现未必是回收。

**正例 1**

> 伏笔「铜钥匙」｜埋设：第0014章｜状态：疑似回收（第0031章 出现同一物件，但未交代来历）｜建议：请作者确认是否算回收；若不回收，建议在第0033-0035章给出交代。

**反例 2（无依据结论）**

> 有三四条伏笔都该收了。

问题：没有条目、没有章号、没有依据。

**正例 2**

> [超期未回收] 伏笔「老周的欠条」｜埋设：第0009章｜已过 34 章｜建议：本卷第0051-0053章回收，或作废（代价：老周这条线失去与主角的绑定）。

**反例 3（悬空指涉漏判）**

正文写「他想起那人说过的话」，但台账里没有「那人」。

正确做法：列为悬空指涉候选，指出章号与摘句，请作者决定是补登还是删改正文。

**反例 4（重复埋设未合并）**

同一枚铜印在第 12 章与第 26 章各被「首次发现」一次。

问题：读者会觉得啰嗦，且两次「首次」互相矛盾。正确做法：合并为一条，把第 26 章那次改写为明确呼应（例如认出旧痕）。

**正例 4**

> [重复埋设] 伏笔「铜印」｜埋设：第0012章（首次获得）｜重复：第0026章（再次「首次发现」，与0012矛盾）｜建议：把0026章改为认出印背旧痕，或删去0012章的获得段落。

## 验收清单

- [ ] 每条结论附章节依据或原文摘录；查不到依据的写「依据缺失」。
- [ ] 未把「疑似回收」直接当成「已回收」。
- [ ] 超期伏笔均给出回收窗口或作废建议（含代价）。
- [ ] 未自动修改 `状态/伏笔台账.md` 的任何状态。
- [ ] 悬空指涉已列出章号与摘句。
- [ ] 结账行给出四类状态计数。
- [ ] 正文检索覆盖每条伏笔埋设章之后的全部章节，未只扫最近几章。
- [ ] 同批问题已按优先级排序（超期优先于重复与悬空）。
