# 角色成长与一致性（character-arc）

## 触发条件

- 作者要求检查某个角色的成长线是否成立。
- 某段正文让人觉得角色「不像他」或「转变得太突然」。
- 关系值发生方向变化，需要确认是否有铺垫。
- 怀疑角色说出或做出超出其已知信息范围的事。

## 输入契约

- **角色卡**：目标、动机、能力边界、性格与语言习惯、已知信息边界。
- **状态快照**：位置、伤势、心理、关系值与最后更新章。
- **待查正文**：需要核对的章节范围，以及变化发生的位置。
- **铺垫材料**：变化发生之前的若干章，用来确认铺垫是否存在。
- 缺角色卡时：先报告缺卡，只能做粗判并标「待核实」，不得凭印象断言 OOC。

检查表与判定阈值见 [角色弧光检查表](references/角色弧光检查表.md)。

## 输出契约

- **三类问题**：无铺垫突变 / 性格漂移（OOC）/ 事实越界，逐条列出，不混写。
- **每条附证据**：角色、涉及字段、正文证据（章号与摘句）、建议补法。
- **建议补法**：写明在哪一章补哪一段铺垫，或写「该角色何时才能知道」。
- **结账行**：`无铺垫突变 N 处 / 性格漂移 M 处 / 事实越界 K 处 / 待核实 J 处`。

## 边界（做什么·不做什么）

**做**

- 逐条比对正文言行与角色卡、状态快照。
- 指出缺铺垫的位置，并给出补铺垫的具体落点。
- 说明事实越界项「该角色何时通过什么事件才能知道」。

**不做**

- 不改正文。
- 不直接改角色卡与状态文件；需要变更时走提案并逐字报出旧值。
- 不因「为了剧情需要」而默认放行；确属作者决定，也要标注为作者决定。
- 不把无证据的判断写成结论；证据不足就记「待核实」。
- 不用「人设崩了」这类笼统评语代替具体字段与证据。

## 步骤

1. **备料**：取本章涉及角色的性格要点、当前状态（位置/伤势/心理/关系）与近期已知信息变化。
2. **对齐**：按角色逐个比对正文言行与角色卡字段，标注不一致处。
3. **查弧光**：对每个心态/立场/关系变化，回溯变化前是否有至少一次可指认的铺垫（事件、对话、观察）。
4. **查越界**：核对角色是否掌握了未被亲历、被告知或可合理推知的信息。
5. **给补法**：为每处问题给出「补铺垫的章与段落」或「告知事件」的具体建议。
6. **结账**：按三类问题汇总，列出待核实项。

### 判断规则

- **变化必须有据**：没有铺垫的突变一律判不通过，并指明应补铺垫的位置。
- **性格看三项**：性格特质、说话风格（口癖/句长/称呼习惯）、处事方式；三项里有两项异常才算漂移。
- **信息边界三来源**：亲历、被告知、可合理推知。三者都不满足即事实越界。
- **作者决定要显式**：如果角色「不像他」是作者的有意安排，标注为「作者决定」，不算漂移但要在报告里记一笔。
- **无证据即待核实**：拿不到角色卡或缺前文时，判「待核实」而不是「通过」。

### 判定前的准备动作

1. 先确定本次要查的角色清单（本章出场的、以及被提及的关键角色）。
2. 为每个角色取出角色卡与状态快照，标出「本次可能被触碰的字段」。
3. 全文检索该角色此前的语言与处事样本各两处，作为比对基线。
4. 标出所有「变化点」（位置、伤势、关系、立场、信息），逐个回溯铺垫。
5. 变化点超过三个时，分批报告，不要一次堆成一大段。

### 与其他技能的边界

- 关系值变化无铺垫，属本技能的突变项；把变化写进台账由 `novel-setting` 负责。
- 伏笔层面的呼应缺失，交 `foreshadow-check`，本技能只判角色自身逻辑。
- 去 AI 味（语言是否像人）不由本技能判，交 `human-linguistics`；本技能只判「是否像这个角色」。

### 字段级比对表

对每个角色逐字段比对，表格留痕：

| 字段 | 角色卡 | 本章表现 | 判定 |
|---|---|---|---|
| 目标 | … | … | 一致 / 偏离 |
| 动机 | … | … | 有据 / 突变 |
| 能力边界 | … | … | 守界 / 越界 |
| 语言习惯 | … | … | 一致 / 漂移 |
| 处事方式 | … | … | 一致 / 漂移 |
| 已知信息 | … | … | 合规 / 越界 |

三项中两项偏离才判 OOC；单项偏离写「轻微偏离」。

### 三类问题的建议写法

- **无铺垫突变**：给「在哪一章补什么」。「第0018章补一次阿贵被救下却不承认的插曲」比「建议补充动机铺垫」有用得多。
- **性格漂移**：给「保持哪一项、更新哪一项」。「他本章改用长句，与角色卡的短句习惯冲突；若为有意转变，请更新角色卡语言习惯字段」。
- **事实越界**：给「何时通过什么事件才能知道」，或给一句改成推测的写法。两者择一，不要只判不给出路。

### 与状态变更的衔接

- 本技能只做判定与建议，不改任何文件。
- 判定需要更新角色卡或状态时，写成提案建议，由 `novel-setting` 执行，且提案必须逐字报出旧值。
- 旧值与台账不一致时，先报「旧值不一致」，停下等作者确认，不按记忆里的版本改。

### 弧光成立的三种常见形态

1. **渐变型**：多次小事件累积，每次幅度小，读者不觉突兀。检查点：是否至少有三次可指认的累积。
2. **触发型**：一次重大事件引发转折。检查点：触发事件的强度是否与转变幅度相称。
3. **反复型**：想改又退回，最终才完成转变。检查点：每次退回是否都有代价，不能原地打转。

不属于以上三种又无铺垫的转变，判「无铺垫突变」。

### 提示写法要求

每条问题至少给三样，缺一不算合格输出：

- **谁**：角色名与涉及字段。
- **什么证据**：章号加摘句，能复现。
- **怎么改**：补铺垫的章与段落，或改成推测的写法，或更新角色卡字段。

只写「疑似 OOC，请作者确认」不算合格，必须把可疑点和依据说清楚。

### 报告示例

```
结论：突变 1 处、漂移 0 处、越界 1 处、待核实 1 处
[突变] 阿贵｜处事方式/立场｜第0022章「他横过去一步」｜变化前 21 章无铺垫｜建议：第0018章补一次被救的插曲
[越界] 沈砚｜已知信息｜第0031章说出妹妹质押细节｜该角色不在场亦无告知｜建议：第0029章补传话，或改为推测句
[待核实] 缺 `设定/人物设定.md`，无法判定老周的语言习惯是否漂移
```

### 常见漏判提醒

- 只查主角，漏查配角与反派；本章出场的都算，哪怕只说了两句。
- 只查性格，漏查「已知信息」栏，事实越界往往比 OOC 更伤。
- 只查本章，漏查变化前的铺垫章；突变判定必须先回溯。
- 只凭一句旁白下结论，漏看同段里的动作与对话。

## 正反例

**反例 1（无铺垫突变）**

> 一直自私怕事的阿贵，在第 22 章突然替主角挡了一刀。

问题：变化前 21 章里没有任何亲历、被告知或心理转折的铺垫，属于无铺垫突变。

**正例 1**

> 突变：阿贵在第0022章挡刀｜涉及字段：处事方式/立场｜证据：第0022章「他横过去一步」｜第0009、0015章他只做旁观｜建议：在0018章补一次阿贵被主角救下但不肯承认的插曲，作为动机铺垫。

**反例 2（事实越界）**

> 沈砚说：「你妹妹抵押在城东的当铺。」

问题：此事仅在第0009章由老周私下与货主谈过，沈砚当时不在场，也无告知情节。

**正例 2**

> 越界项：沈砚说出妹妹被质押的细节（第0031章）｜该角色当前不该知道｜建议：或在第0029章补一段老周托人传话的告知，或将本句改为沈砚的推测（「是不是……在城东」）。

**反例 3（笼统评语）**

> 这章人物有点崩。

问题：无角色、无字段、无证据。应写明是哪一项（性格/语言/处事）与哪一句。

**反例 4（把作者决定当 OOC）**

作者明确说「这一章我要让他彻底变一个人」，报告仍判「OOC，建议改回」。

问题：作者决定属有意安排，应标注为「作者决定」并记录，不作为问题；但可提示「转变缺铺垫，建议补一次触发事件」。

**正例 4**

> 标注：沈砚第0040章立场反转属作者决定（作者在对话中确认）｜仍提示：转变前 3 章无触发事件，建议在第0037章补一次亲历冲击，或由作者接受无铺垫的写法。

## 验收清单

- [ ] 所有判定都引用正文证据；无证据的判「待核实」而不是「通过」。
- [ ] 突变项给出了具体补铺垫的章与段落。
- [ ] 事实越界项说明了「该角色何时通过什么事件才能知道」。
- [ ] 性格漂移判定基于三项口径，至少两项异常才下结论。
- [ ] 属于作者有意安排的变化已标注为「作者决定」。
- [ ] 未改正文、未直接改角色卡与状态；状态变更以提案提交且含旧值。
- [ ] 变化点已逐个回溯铺垫，未只检查最近一章。
- [ ] 与伏笔、去 AI 味相关的问题已归到对应技能，未混入本报告结论。
