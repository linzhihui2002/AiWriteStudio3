# 快速启动指南

> 5 分钟跑通「AI 小说创作工作台」。完整说明见 [README](../README.md)、[开发文档](AI小说创作工作台-开发文档.md)、[项目技术文档](AI小说创作工作台-项目技术文档.md)和[近期对话修改与优化说明](近期对话修改与优化说明-2026-09-24.md)。

## 环境要求

| 依赖 | 版本要求 | 用途 |
|---|---|---|
| Python | ≥ 3.11 | 后端 |
| Node.js | ≥ 20 | 前端构建 + 内置 dsh |
| npm | 随 Node | 依赖安装 |

## 一、安装（首次）

在项目根目录 `d:\desktop\AiWriteStudio3` 执行：

```powershell
# 1) Python 虚拟环境 + 后端依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r workbench/backend/requirements.txt

# 2) 前端依赖 + 构建
npm --prefix workbench/frontend install
npm --prefix workbench/frontend run build

# 3) 内置 dsh（vendor 本地安装，独立 DSH_HOME，不碰全局 npm 与 ~/.dsh）
.\.venv\Scripts\python.exe workbench\cli\setup_dsh.py
```

## 二、启动

```powershell
.\.venv\Scripts\python.exe -m workbench.backend.app
# 打开 http://127.0.0.1:8790
```

- 端口按项目红线固定 **8790**；3080 / 8765 / 3456 为禁用端口，8790 被占用时明确报错。
- 开发模式（热更新）：终端 A 跑上面的后端；终端 B 执行 `npm --prefix workbench/frontend run dev`（Vite 代理 `/api` 到 8790）。

## 三、首次使用（4 步出稿）

1. **设置 → 模型供应商**：填 `baseURL` 与 API Key → 拉取模型 → **勾选并批量添加为一个供应商的多个模型**（可分别设上下文窗口 / 最大输出）→ 设「全局默认模型」→ 健康检查 → 启用。保存与启用会自动投影到内置 dsh；「投影到内置 dsh」保留为手动修复入口。
   Key 存于 `.workbench/secrets.json`（Windows DPAPI 加密），不入 Git、不进日志。
2. **书架 → 新建项目**：填书名/题材/主角/一句话设定 → 自动生成 `projects/{书名}/` 工作区。
3. **大纲页**：写灵感 → 生成候选（每批 2-3 个累计追加、自动去重，可对单个候选对话优化）→ 锁定 → **冻结**（冻结后章节生产才放行；可随时取消冻结继续编辑）。
4. **编辑器**：新建章节 → 生成/冻结章节合同 → 跑 8 步循环 → 到 **收件箱** 审差异并应用落盘。

对话中直接修改本书文件时，先检查会话权限（请求批准 / 帮我批准 / 完全访问）和“仅讨论”开关；默认「帮我批准」，只有删除、移动才弹批准卡，改权限无需新开对话。附加的参考文件与正文目标章节会分别显示；编辑器也会标出当前实际文件路径。章节标题可直接输入普通文字，磁盘文件名自动采用 `第NNNN章.txt` 编号（正文纯文本，标题/状态/字数在库）；每章字数区间默认 2000–4000 汉字，可在设置与对话面板调整。

全局区还提供：**收件箱**（AI 产出的 diff 审阅与应用）、**仪表盘**（Token 用量与成本）、**工作流**（编排与批量产章）、**生图工坊**（配置图片供应商 → 生成 → 画廊管理，产物在 `.workbench/images/`）、**设置**。项目区另有 **知识库与图谱**（语义检索与关系图谱）、**审稿中心**、**设定卡片** 与 **项目设置**（本书权限与字数区间默认值）。

## 四、自检（可选）

```powershell
.\.venv\Scripts\python.exe -m pytest workbench/backend/tests -q
# 大纲候选追加、去重、连续优化与冻结切换专项（临时项目 / 模拟模型）
.\.venv\Scripts\python.exe -m pytest workbench/backend/tests/test_outline_candidates.py workbench/backend/tests/test_outline_freeze.py workbench/backend/tests/test_content.py -q
.\.venv\Scripts\python.exe workbench\cli\check_no_bare_dsh.py    # 隔离红线静态扫描
```

编辑器幽灵续写的[浏览器回归模块](../workbench/frontend/tests/ghostText.browser.acceptance.cjs)需先执行 `npm --prefix workbench/frontend run build`，再在浏览器自动化中调用 `runGhostTextAcceptance(page)`（支持 Tabbit 的 Page）。它验证章首/中间点击追加章末、撤销与焦点、Tab/Esc、连点、组合输入，以及改文/切章后的旧响应失效；使用生产 dist 和合成 API，不调用后端/模型或修改真实书稿，不接入 `npm test`。

## 常见问题

| 现象 | 处理 |
|---|---|
| 启动报端口占用 | 确认 8790 未被占用；禁用 3080/8765/3456 不可改用 |
| dsh 不可用 | 语义任务自动降级 `direct-api`；重跑 `workbench\cli\setup_dsh.py` |
| 前端页面空白 | 确认已执行 `npm --prefix workbench/frontend run build`（后端服务 `dist/`） |
| 想清空重来 | 删除 `.workbench/`（索引/任务可重建）；`projects/` 是正文事实源，勿删 |

## 隔离红线（速记）

1. 只用独立 `DSH_HOME = .workbench/dsh-home`，永不读写 `~/.dsh`；
2. 只调 vendor 内置 dsh（经 `workbench/backend/engine/dsh_paths.py`），禁止裸 `dsh` 命令；
3. 端口 8790，禁用 3080/8765/3456；
4. `projects/` 第三方素材只读，引入前查 `docs/third-party-notices.md`。
