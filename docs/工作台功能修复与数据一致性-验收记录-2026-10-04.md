## 1. 实际实现

| 问题 | 实现与实际行为 |
| --- | --- |
| 章节树状态无法修改 | 状态变为草稿／完成／发表菜单，可在打开设定、账本等材料时操作指定章节。仅合并返回的状态，不替换未保存正文或编辑基准；同步提交锁阻止快速重复操作，同书目录在切文件后仍刷新。 |
| 软审长输入失败、诊断混淆 | 自有 Node stdin 桥接从二进制管道读取完整 UTF-8，经 `dsh_paths` 加载锁定 vendor，不经过 `.cmd`、不把正文传入操作系统 argv。响应提供源版本、任务号和脱敏原因，区分引擎失败、结构错误、原文核验失败与有效空建议。 |
| 三种操作切换不换结果 | 逐项审稿、去 AI 味软审、提取四件套使用独立结果模式和开始按钮。切换模式不会调用模型，各自保存结果、加载与错误；旧章/旧书响应失去提交资格，改稿后标记旧报告。质量矩阵按门名称映射，补齐格式门及硬门禁总状态。 |
| 文风认可不能取消、重复加权 | 一章一条当前记录，重复采样更新；项目限定取消接口即时退出写作参照和统计。正文版本失效要求重新认可；省略备注保留、显式空值清除。迁移归档被合并/变更的原始行，最新授权状态胜出，取消不会被旧认可复活；有效集不再截取 100 条。 |
| 四件套重复、风险写回 | 提取有结构/有限数值/逐字依据核验，AI 与规则重合事件去重，正文不同位置独立保留。每书/章节/正文 hash/抽取版本/模式持久记录提交，同版重放不调用模型、不写文件、不新建候选，并发忙碌明确反馈。更改正文后只替换该章托管块，人工材料受保护；提交中断恢复或回退不能覆盖后来人工修改。 |
| 角色状态片段覆盖整份文件 | 每章合成一份完整状态候选，保留其他角色、字段、格式；应用核验来源正文与目标状态版本。旧片段基于持久基准全文合成，无法安全定位则拒绝。目标变更后可在收件箱显式重提完整差异；正文变化或候选人工编辑时拒绝沿用旧字段。 |
| 已确认伏笔丢失 | 依据扩展时，同事件可唯一对齐则保留回收状态与计划；无法对齐则报冲突。改稿未再提及的已确认条目/计划仍保留并提示。旧系统精确格式且章节、事件、依据均唯一时安全接管；其余历史条目保留并报告可能重复。 |
| 设定资料解析与界面 | 统计改为响应式数字网格和可切换分类入口，详情紧凑。支持标题、属性表、对象表、双侧时间线与伏笔列表，说明小节不冒充实体；计划伏笔与已埋设伏笔分别计数。`rel_path` 与来源标注 ID 分开，未知来源/缺字段有操作入口，材料定位和上下文使用真实路径。 |
| 大纲、卡片、收件箱、拆书异步错误 | 统一同步提交锁与项目/条目/表单版本保护；迟到响应不能清空新输入或关闭新表单。大纲保存使用提交快照，锁定保留刚生成的历史。卡片字段改名/删除使用显式编辑与源 hash，无法安全独立修改的原文只禁用对应控件并提供材料定位。设定分类切换后拒绝旧分类刷新，回收计划输入随切书清理。 |

四件套的用途与操作结果均在审稿页说明：时间线承接日期与事件顺序，角色状态承接位置、持有物、伤势等，伏笔台账管理埋设与回收，资源账本登记收支与待核实结余。核验后的时间线、伏笔及账本自动更新；角色状态进入收件箱核对。审稿/软审仅报告和产出建议，不自动修改正文。人物出场保留为出场列表，不再自动将整章摘要写进每个人的记忆。
