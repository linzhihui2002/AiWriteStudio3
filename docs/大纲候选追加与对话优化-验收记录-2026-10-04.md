# 大纲候选追加与对话优化 · 验收记录

日期：2026-10-04。范围：大纲规划页、候选元数据服务、候选生成 / 优化 / 锁定接口。实现契约详见 [项目技术文档 §7.2](AI小说创作工作台-项目技术文档.md#72-大纲规划与冻结)。

## 实际行为

- 每次生成追加到本书候选列表，保留旧标题、正文及顺序。新候选使用稳定 ID 和累计编号。
- 模型收到已有候选以避免重复；落盘前忽略包装标题、空白与标点做正文去重，并过滤 92% 以上的近似重复。提交在按书锁内重读最新数据，避免并发覆盖。
- 生成失败、空结果或全部重复均保留旧候选并说明原因，AI 故障不再生成占位候选替代原内容。
- 生成按钮显示「正在生成候选…」，页面同时出现等待提示；重复点击只提交一次。已有候选时按钮显示「继续生成」。
- 每张候选卡可选择「对话优化」。每轮将当前候选及历史对话交给模型，成功追加新版本并自动选中，原版可继续比较 / 另开优化分支。
- 优化区显示等待状态；失败保留原候选和输入意见。候选间未发送的意见分别缓存，发送期间追加的输入保留供下一轮使用。
- 对话与版本关系保存于本书 `.meta/outline.json`；刷新后选回对应候选即可继续查看历史和优化。仅明确锁定后写正式大纲，未保存正式稿的原有保护继续有效。
- 优化允许保留正文中的小幅实质变更，仅改变包装标题或标点不创建新版本。文本去重不能保证识别一切语义相同但大幅改写的故事方案。

## 同日补修：冻结 / 取消冻结

原页面在冻结后禁用冻结按钮，服务也只有冻结入口，无法取消。现新增 `POST /api/projects/{project_id}/outline/unfreeze`（无需 body），冻结后的同一按钮显示「取消冻结」。取消只将本书 `.meta/gates.json` 的 `outline_frozen` 改为 `false`、冻结时间改为 `null`，保留其他门禁、正文、候选 / 对话及合同，记录取消操作。冻结和取消均在项目锁内合并最新门禁数据；取消后 CHECK 恢复要求先冻结大纲。

页面切换请求显示「正在冻结…」 / 「正在取消冻结…」，防重复提交与切书迟到响应继续生效。取消允许保留未保存的正文输入；再冻结时有未保存修改则提示先保存，不对磁盘旧稿发冻结请求。取消成功后可保存修改，再次冻结，仍可继续取消。
