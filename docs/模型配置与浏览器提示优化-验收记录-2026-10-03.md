# 模型配置与浏览器提示优化验收记录 · 2026-10-03

本轮处理模型配置保存时出现浏览器密码保存提示，以及供应商长表单字段错位、模型额度分散和窄屏可用性问题。保留开工时未提交的工作树，在既有前端交互上定向修改；实现事实见[项目技术文档 §3.11、§4.6、§8.2](AI小说创作工作台-项目技术文档.md)。本记录汇总本轮代码、离线回归、实际浏览器布局与交互检查；浏览器内部 UI 的观察边界另列。

## 审计范围与发现

静态审计覆盖 `workbench/frontend/src/` 全部自有 TS/TSX、JS/JSX/HTML 源码、前端 `index.html`、入口/Vite 配置，以及相关 backend/cli 自有代码；不遍历 vendor、构建产物或小说项目。未读取真实 Key、用户全局 `.dsh` 或作者小说正文，未操作实际供应商配置、模型服务或书稿。修改未引入第三方代码、文本或新依赖。

| 入口 | 原因/判断 | 当前处理 |
|---|---|---|
| 模型供应商和生图供应商 API Key | 原 `type="password"` 与 `autocomplete="new-password"` 仍可被浏览器识别为新账号凭据；禁止自动回填不等于禁止保存密码提示 | 共用 `CredentialInput`：普通文本输入配视觉掩码，主动显示、离开后隐藏；已存 Key 不回填，留空继续保留原值 |
| 卡片导出复制、完整回复复制 | 原 `navigator.clipboard.writeText()` 的权限处理受浏览器策略影响 | 同步 `copyTextToClipboard()`，只在用户点击中执行兼容复制；失败 Toast 和手动选择提示，不追加权限请求 |
| 作者问题的“其他回答” | `required` 与默认表单校验保留了浏览器校验气泡入口 | `noValidate` + `aria-required`，保留现有 `questionResponse()` 非空/选项校验及提交状态 |
| 原生 alert/confirm/prompt/open、离页确认 | 已有应用内确认和覆盖层；未发现自有前端的直接原生调用/监听 | 增强静态守卫，继续使用 `useConfirm` / `Modal` / `Drawer` / Toast |
| 通知、摄像头/屏幕、定位、凭据管理、文件系统权限 API | 未发现自有 UI 的直接请求入口；后端未发现 HTTP Basic 认证弹窗或开浏览器调用 | 将高风险入口纳入静态守卫 |
| 显式文件选择及下载 | 作者明确触发的上传、导入和导出行为 | 按技术文档既有约定保留 `<input type="file">` 和下载链接 |

守卫覆盖直接调用与已列出的属性写法；不追踪动态 API 名称、别名或外部扩展，也不能观察浏览器内部密码管理器 UI。浏览器设置、第三方扩展、操作系统文件选择窗口与自动化页面 DOM 观察有不同边界，应在浏览器验收记录中分别说明。

## 实现与验收对应
